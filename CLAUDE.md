# CLAUDE.md

Project guidance for Claude Code (and any agent) working in this repo. Keep it short; link the docs
rather than restating them.

## What this is

**Govori** — an AI voice tutor for real, everyday Ljubljana Slovene. Mobile-first PWA + Node server.
A learner holds a button and speaks (mixed English/Slovene is fine); the server understands, replies
in native-quality Slovene, and corrects by recast. Scenarios are **generated by an engine**, not
hand-written. See [README.md](README.md) for the product framing.

## Run & verify

```bash
npm run dev            # http://localhost:8787 — hold the button, speak, release
npm run probe:e2       # understand+tutor adapter reachable
npm run probe:e3       # voice adapter returns real audio (writes fixtures/out/e3-probe.mp3)
npm run replay         # recorded clips → full pipeline → audio, within latency budget
npm run test:mastery   # the deterministic mastery-loop rules
```

**Testing philosophy: test the seams with real services, observe the pipeline live, never mock the
heart.** Don't add mock-fixture death-marches around the speech integration — the probes and replay
exist to exercise the real thing.

## How it's built

- **The app owns the pedagogy, not the model.** The value is a structured mastery scaffold that
  constrains the LLM hard (short tutor turns, simple Slovene, recast corrections, learner does most
  of the talking). The server — not the model — owns the `pending → recast → completed` rules and
  rebuilds the prompt from objective state each turn. → [docs/mastery-loop-spec.md](docs/mastery-loop-spec.md)
- **Provider-agnostic.** Speech (E3) and understand+tutor (E2) run through swappable adapters in
  [server/adapters/](server/adapters/); the swap point is one `.env` line. → [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)
- **Scenarios are data**, one JSON per scenario in [server/scenarios/](server/scenarios/) (café,
  bakery, butcher today).

## The scenario engine — the important working agreement

New scenarios are authored by the **`create-scenario` skill**
([.claude/skills/create-scenario/SKILL.md](.claude/skills/create-scenario/SKILL.md)), which
orchestrates two subagents — `slovenian-author` (writes the Slovene) and `scenario-critic` (an
independent reviewer) — under the responsibility contract in
[docs/scenario-engine-contract.md](docs/scenario-engine-contract.md).

**Rules — do not bypass these:**
- **Never freehand a scenario.** Single-agent, hand-written scenarios were tried and failed
  (ambiguous flashcards, textbook-not-native Slovene). The engine and its gates exist specifically to
  prevent that. Author through the skill.
- **`npm run lint:scenario` must pass (exit 0) *before* the critic reviews.** Deterministic checks
  first, fuzzy judgment second.
- **Keep judgment / logic / generation separate** ("C decides and specifies; L assembles and calls;
  G renders"). The orchestrator emits structured specs; code assembles prompts and calls generators;
  the author/critic never write files or invoke generators. See the contract for the J/L/G split.
- After approval: `npm run build:assets` materializes audio + images; the scenario auto-appears in
  the picker. `npm run prune:assets` GCs orphaned image assets.

## Conventions

- **Secrets in `.env` only** — never the shell, commits, or chat. See [docs/SECRETS.md](docs/SECRETS.md).
- Model ids and the Slovenian voice id are env-configurable; verify against current provider docs
  before assuming a value.
- `.scratch/`, `.consensus-runs/`, `/assets/`, and `.claude/settings.local.json` are local-only
  (gitignored). Don't rely on them being present for anyone else.
