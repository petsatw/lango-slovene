# Slovene A1 Content Taxonomy — canonical reference

**Status:** canonical. This replaces the 6 hand-authored placeholder competencies in
`server/catalog/a1-map.json`. It is the source list that every catalog learnable is mapped *against*
(D5i fold-in, D5ii `lint:a1`).

**Source framing:** the *shared core content* mastered and reused across all four skill modes (Reading,
Listening, Writing, Speaking). Deliberately formulaic, high-frequency, survival-oriented — following the
official *Preživetvena raven za slovenščino* (2016), the A1 exam structure, CEFR A1 descriptors, and
available A1 core lexical resources (≈350 A1-core lemmas + broader A1 inventory of ~900–1,000 items).

> The **Implementation binding (MVP)** section at the end records how this maps onto the current app and
> the honest scoping limits. The spec itself (§1–§4) is preserved faithfully as the reference.

---

## 1. Foundational Shared Layers (Cross-Modal)

These layers underpin every theme and every skill.

### 1.1 Phonological / Orthographic Competence
- Full Slovene alphabet + letter names (for spelling names, addresses, emails).
- Sound–spelling correspondences, including digraphs (*lj, nj, dž*) and the distinction between *c/č, s/š, z/ž*.
- Basic stress patterns and clear intelligibility of high-frequency words (production prioritises being understood over native-like accent).
- Numbers 0–100 (and higher for prices/years in recognition), dates, times (digital and analogue), quantities, measurements.
- Spelling of personal names, street names, common place names, and basic email conventions (*afna, pika*).

### 1.2 Morphosyntactic / Structural Competence (Highly Formulaic)
- Present tense of high-frequency verbs (*biti, imeti, iti, delati, govoriti, jesti, piti, živeti, priti, vedeti, želeti, gledati, pisati, brati, prositi, kupiti, plačati…*).
- Basic gender and number agreement (masculine/feminine/neuter; singular/plural) in formulaic contexts.
- A very limited set of case forms used formulically (especially nominative, accusative, locative with common prepositions *v, na, pri, iz, od, do, s/z*).
- Question formation with key interrogatives (*kdo, kaj, kje, kdaj, kako, koliko, od kod, kam, zakaj*).
- Negation (*ne + verb*, *nimam, ne govorim…*).
- Simple connectors (*in, ampak, ker, potem*).
- Basic word order in simple declarative and interrogative sentences.
- Formulaic fixed phrases that are treated as unanalysed chunks (not generative grammar).

### 1.3 Core Lexical Inventory
- A1-core (~350 highest-frequency lemmas that appear across virtually all A1 materials) + A1-larger set (bringing the productive target to roughly 900–1,000 items).
- Organised by the 10 thematic domains below + a small set of universal items (numbers, time, colours, basic adjectives of size/quality, common prepositions, politeness markers).
- Distinction between *recognition vocabulary* (slightly wider) and *productive vocabulary* (smaller, highly practised set of chunks).

### 1.4 Pragmatic / Sociolinguistic Competence
- Greetings and leave-takings (*Dober dan, Zdravo, Živjo, Nasvidenje, Adijo, Lahko noč…*).
- Politeness formulas (*prosim, hvala, oprosti(te), prosim za…, lahko…?*).
- Tikanje vs vikanje awareness (basic recognition and simple use).
- Expressing understanding / non-understanding (*Razumem / Ne razumem. Ponovite, prosim.*).
- Basic confirmation / denial (*Da, ja / Ne*).
- Simple expressions of preference (*Všeč mi je / Ni mi všeč*).

## 2. Crucial Dichotomy: Reception vs Production

Most core content is shared, but the *depth of control* differs:

| Aspect | Reception (Listening + Reading) | Production (Speaking + Writing) |
|--------|----------------------------------|---------------------------------|
| Vocabulary | Wider recognition set; can extract meaning from partially known items with context | Smaller active set; heavy reliance on practised formulaic chunks |
| Grammar | Tolerance for incomplete or non-standard forms if meaning is clear | Limited productive control; prioritise intelligibility and formulaic correctness |
| Fluency / Processing | Can use context, pictures, slower speech, repetition | Short utterances, pauses, searching for words are normal; preparation time allowed (especially Speaking) |
| Task Support | Non-verbal cues, visuals, multiple-choice, matching heavily used | Guided production, model phrases, form-filling scaffolds |
| Success Criterion | Extract key factual information (time, place, price, name, yes/no) | Transmit a clear, simple message that a cooperative interlocutor can understand |

The same lexical items, themes, and functions appear in all modes, but production tasks train a stricter
subset and emphasise chunking + intelligibility.

## 3. Thematic Taxonomy (10 Core Domains)

Each domain contains: sub-topics / content inventory · key language functions (CAN-DO) · typical formulaic
patterns / sample exponents (shared across modes) · mode-specific realisation notes.

### 3.1 Osebna identiteta (Personal Identity)
- **Content:** Name, surname, age, gender, nationality/origin, languages spoken, address, phone, email, family members, occupation/education status, personal documents, filling forms.
- **Functions:** Give and ask for basic personal data; introduce self and others; fill in personal details on forms; understand questions about self.
- **Formulaic patterns:** *Sem + ime. Pišem se… Živim v… Stara/star sem… let. Sem iz… Govorim… / Ne govorim… Imam… otrok. Delam kot… / Sem študent(ka). Kako ti/vam je ime? Od kod ste? Koliko si star(a)?*
- **Mode notes:** Heavy form-filling in Writing/Reading; personal introduction monologue and Q&A in Speaking; short recorded questions in Listening.

### 3.2 Stanovanje, bivanje in okolje (Housing, Living, Environment)
- **Content:** Types of dwelling (hiša, stanovanje, blok, soba), rooms, basic furniture/equipment, floor level, garden, neighbours, pets, weather, basic environment (hills, river, city).
- **Functions:** Describe where one lives; ask/answer about housing; understand simple weather forecasts and notices about the building; write a short note to a neighbour/landlord.
- **Formulaic patterns:** *Živim v stanovanju/hiši. Imamo… sob. V kuhinji je… Pred hišo je vrt. Dvigalo ne dela. Jutri bo sončno/deževno.*
- **Mode notes:** Picture description (Speaking/Writing); matching notices or weather icons (Reading/Listening).

### 3.3 Telo in zdravje (Body and Health)
- **Content:** Body parts, basic feelings/symptoms (*glava me boli, imam vročino*), common illnesses, medicines, doctor/pharmacy visit.
- **Functions:** Say how one feels; name body parts; request help or medicine; understand simple medical instructions or questions.
- **Formulaic patterns:** *Glava me boli. Imam vročino. Kje boli? Potrebujem zdravilo. Pri zdravniku…*
- **Mode notes:** Role-play at the doctor (Speaking); short dialogues or notices (Listening/Reading); simple symptom description (Writing).

### 3.4 Hrana in pijača (Food and Drink)
- **Content:** Common foods and drinks, meals, ordering in a café/restaurant, basic preferences, quantities.
- **Functions:** Order food and drink; express likes/dislikes; understand menus or simple orders.
- **Formulaic patterns:** *Prosim eno kavo / vodo / sendvič. Všeč mi je… / Ne jem… Koliko stane?*
- **Mode notes:** Ordering role-play (Speaking); menu reading + price extraction (Reading); short service dialogues (Listening).

### 3.5 Vsakdanje življenje in prosti čas (Everyday Life & Free Time)
- **Content:** Daily routine, times of day, clocks, basic hobbies, TV/radio, simple social activities.
- **Functions:** Talk about daily schedule and free-time activities; understand simple timetable information.
- **Formulaic patterns:** *Zjutraj… / Popoldne… / Zvečer… V prostem času… grem na sprehod / berem / gledam televizijo.*
- **Mode notes:** Simple routine monologue (Speaking); timetable matching (Reading/Listening).

### 3.6 Nakupovanje in storitve (Shopping & Services)
- **Content:** Shops, post office, bank, police, prices, money, quantities, basic clothing, packaging.
- **Functions:** Buy goods; ask about price/quantity; understand simple service interactions and price tags.
- **Formulaic patterns:** *Koliko stane? Prosim… / Želim… Imate…? Plačam z gotovino / kartico.*
- **Mode notes:** Transactional role-play (Speaking); price extraction and form-like notices (Reading/Listening).

### 3.7 Osebna razmerja (Personal Relations / Social Formulas)
- **Content:** Greetings, thanks, apologies, invitations, wishes, basic social exchanges.
- **Functions:** Initiate and close simple social contact; express basic politeness.
- **Formulaic patterns:** *Dober dan. Hvala. Oprosti(te). Prosim. Lepo se imej(te). Vabilo…*
- **Mode notes:** Embedded in almost every Speaking interaction; short written messages with openings/closings (Writing).

### 3.8 Izobraževanje (Education)
- **Content:** Types of school/course, basic school subjects/items, course enrolment.
- **Functions:** Talk about one's studies or course; fill in simple enrolment forms; understand basic course information.
- **Formulaic patterns:** *Hodim na tečaj… / Študiram… Prijavljam se na…*
- **Mode notes:** Form-filling (Writing/Reading); short course announcements (Listening).

### 3.9 Delo in poklic (Work & Profession)
- **Content:** Common occupations, workplace, basic job-related personal information.
- **Functions:** State occupation and workplace; understand simple job-related questions or notices.
- **Formulaic patterns:** *Delam kot… / Sem… Delam v… / Na gradbišču / v bolnišnici.*
- **Mode notes:** Personal information exchange (Speaking); short job notices or forms (Reading).

### 3.10 Promet, potovanje in usmerjanje (Transport, Travel & Orientation)
- **Content:** Means of transport, tickets, directions, places, basic travel needs.
- **Functions:** Ask for and give simple directions; buy a ticket; understand transport announcements and signs.
- **Formulaic patterns:** *Kje je…? Kako pridem do…? Ena vozovnica, prosim. Avtobus / vlak gre ob…*
- **Mode notes:** Direction role-play and picture-based description (Speaking); signs, timetables, announcements (Reading/Listening).

## 4. Implementation Notes for the App

- **Shared content pool:** All vocabulary, formulaic chunks, and functions live in one master inventory tagged by theme + skill mode + recognition/production status.
- **Progress tracking:** Each theme has a mastery score. Skill progress bars aggregate performance on theme-linked tasks, weighted by how heavily the official exam uses that content.
- **Scaffolding:** Production tasks always offer model phrases or preparation time; reception tasks lean on visuals and slower/clearer input.
- **Assessment alignment:** Micro-tasks should closely mirror official exam item types (form filling, matching dialogues to situations, short personal messages, picture description, transactional role-play, extraction of time/price/place).
- **Success threshold:** Overall A1 readiness requires solid coverage of the core formulaic inventory across the 10 themes *and* ≥60%-equivalent performance in each of the four skill modes.

## Implementation binding (MVP) — how this taxonomy maps onto the app

*This section is the design record for D5. It is NOT part of the source spec; it states how §1–§4 bind to
the current architecture and where the MVP honestly falls short of the full framework. No A1 scoring engine
is built (guardrail: no A1 engine, no auto-competency-assignment).*

> **Adopted direction (not yet implemented) — see [dialogue-difficulty-model.md](dialogue-difficulty-model.md).**
> This `a1-map` is the **narrow curated CORE** and stays narrow. A **broader "A1 tag" on catalog learnables**
> (a superset, CORE ⊆ tagged) is the primary signal `lint:a1` reads, so the lint is a **difficulty yardstick**
> (basic = ≥80% core · intermediate = ≥80% tagged-A1 · advanced = beyond). New catalog items get a deliberate
> tag-or-not-A1 decision at mint — judged on merit and tagged when the item is A1 material.

**Competency buckets = 4 foundational layers + 10 thematic domains (14 total).** The `a1-map.json`
`competencies` list is regrown from the 6 invented placeholders to these 14 grounded buckets. Each carries
a `kind: "foundational" | "thematic"` so the readiness UI can group them. Thematic buckets carry their
CAN-DO functions and sample exponents from §3.

**Learnable → competency is many-to-many.** A single learnable maps into *both* a thematic domain and one or
more foundational layers — e.g. a pattern like `Stara sem ___ let` maps to **3.1 Personal Identity** *and*
**1.2 Morphosyntax** *and* **1.1 (numbers)**. `lint:a1`'s rule is *every learnable maps to ≥1 competency (of
either kind) or is on the explicit `excluded` list* — it does **not** require every competency to hold ≥N
learnables (a foundational layer may be sparsely covered by the shipped scenarios; the coverage report
surfaces that, it is not an error).

**The catalog is the PRODUCTION inventory only.** The minting rubric (D4) mints a learnable iff the learner
is expected to PRODUCE it; NPC-only receptive lines are never minted. So the catalog *is* the production
subset of §1.3 / §2. The wider **recognition** inventory is **out of scope** for now — `lint:a1` coverage is
scoped to produced learnables, so it never demands mapping recognition-only items the catalog does not hold.

**The MVP exercises 3 of the 4 skill modes; Writing is excluded by design.** The rehearsal-dialogue surface
covers **Speaking + Listening + Reading** — every audio clip is always paired with its text, so Reading is
exercised alongside Listening. **Writing is intentionally not produced**: Speaking and Listening are the key
barriers this app is built to address, and Reading rides along for free with the paired text. This is a
product decision, not a missing surface. Consequences:
- The §4 success threshold ("≥60%-equivalent in EACH of the four skill modes") is computed over the **three
  in-scope modes** (Speaking, Listening, Reading). The readiness surface marks **Writing** as **"out of scope
  by design"** — never "not yet exercised," and never a blocker to A1-readiness as this app defines it.
- `mode` is carried on each learnable→competency ref as metadata (which in-scope modes exercise it), but no
  weighted cross-mode aggregation is built this session.

**Exam-usage weighting (§4) is metadata, not an engine.** Weights may be recorded on competencies but no
weighted scoring is computed now — deferred with the rest of the A1 scoring engine until ROADMAP item 5.

**Schema delta for `a1-map.json` / `server/a1.ts` (built in B4):**
- `competencies[]` grows to the 14 buckets; add `kind: "foundational" | "thematic"`; thematic buckets add
  `functions[]` (CAN-DO) and `exponents[]` (sample formulaic patterns).
- learnable refs may carry optional `mode[]` (subset of `["reading","listening","writing","speaking"]`) and
  `status: "production"` (default; `recognition` reserved, unused in MVP).
- optional top-level `excluded[]` list of learnable ids deliberately unmapped (keeps `lint:a1` honest).
- `loadA1Map`'s existing forward check (every listed learnable exists in the catalog) stays; `lint:a1` adds
  the **reverse** check (every catalog learnable is mapped or excluded) + ref-resolution + coverage print.
